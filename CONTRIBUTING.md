# Contributing to Nota

## Before contributing

- Read `README.md`, `CHANGELOG.md`, `SECURITY.md`, `docs/PROJECT_WORKFLOW.md` and `docs/TESTING.md`.
- Search existing issues before opening a new one.
- Do not include secrets, personal data or generated production data.

## Contribution flow

1. Open or reference an issue describing the problem or proposal.
2. Create a short-lived branch from `main`: `feature/<topic>`, `fix/<topic>`, `docs/<topic>` or `refactor/<topic>`.
3. Make focused, atomic commits using [Conventional Commits](https://www.conventionalcommits.org/).
4. Run the validation commands documented in `docs/TESTING.md`.
5. Open a pull request explaining the change and referencing the issue.
6. Rebase on `main` if requested; after merge, delete the branch.

## Pull request expectations

- Keep the scope focused.
- Update user-facing documentation, configuration examples and roadmap entries where applicable.
- Explain any intentional compatibility or migration impact.

## Code of conduct

Be respectful. Harassment, discrimination, deliberate malice and disclosure of private information are not accepted.
